# Архитектурные диаграммы

Документация хранится как код в формате PlantUML и версионируется вместе с реализацией:

- [`c4.puml`](c4.puml) — C4 Level 2, границы контейнеров и направления интеграций;
- [`cjm-user.puml`](cjm-user.puml) — путь пользователя от каталога до результата заказа;
- [`cjm-restaurant.puml`](cjm-restaurant.puml) — путь заведения от очереди до готовности
  или отклонения заказа;
- [`database.puml`](database.puml) — ER-схема PostgreSQL, ключи и важные инварианты.

Диаграммы автономны и не загружают внешние библиотеки через `includeurl`. Их можно открыть
расширением PlantUML для IDE или сгенерировать стандартным PlantUML CLI:

```bash
plantuml docs/*.puml
```

Тест `tests/test_documentation.py` проверяет базовую структуру исходников, отсутствие
сетевых зависимостей и соответствие набора таблиц ER-схемы SQL-миграции.

## Принятые границы

Kitchen API владеет каталогом и жизненным циклом заказа. Restaurant API — пример внешней
системы партнёра: он не подключается к PostgreSQL, а читает очередь и меняет статусы только
через закрытый HTTP API. В MVP доставка и завершение заказа оставлены точками расширения:
схема БД допускает эти состояния, но партнёрский API завершает реализованный сценарий на
статусе `ready`.
